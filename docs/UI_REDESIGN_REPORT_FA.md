# گزارش بازطراحی رابط نسخه‌یاب

تاریخ: ۲۰۲۶-۱۰-۱۸

## دامنه و روش

بازطراحی روی برنامه واقعی React و API موجود انجام شد؛ API نمایشی یا داده ثابت جایگزین مسیرهای عملیاتی نشد. روش مهارت‌های UI UX Designer شامل بررسی تجربه موجود، بازطراحی و تبدیل مستقیم به کد استفاده شد. این بررسی، ارزیابی مهندسی و آزمون مرورگر است؛ پژوهش یا تأیید کاربران واقعی ادعا نمی‌شود. نام نهایی محصول طبق درخواست کاربر «نسخه‌یاب» است و در وب، PWA، Android، iOS و عنوان Swagger یکسان شد؛ شناسه‌های فنی برنامه و لینک‌های قبلی تغییر نکردند.

## تغییرات تجربه کاربری

- صفحه اصلی با فضای روشن، سلسله‌مراتب خوانا، CTA مشخص، راهنمای چهارمرحله‌ای، پرسش‌های متداول و ورود روشن به پنل داروخانه بازطراحی شد.
- فرم بیمار به سه گروه اطلاعات بیمار، بیمه و توضیحات تقسیم شد؛ پیام خطای هر فیلد، خلاصه خطا، راهنمای کدها و دکمه ارسال مناسب موبایل اضافه شد.
- پیگیری با لینک خصوصی یا کد پیگیری و کد دسترسی انجام می‌شود؛ لینک ورودی فقط تجزیه می‌شود و کاربر به سایت دیگری هدایت نمی‌شود.
- صفحه ثبت موفق، زمان اعتبار، کپی کد و لینک، نتایج مرتب‌شده، انتخاب داروخانه و تأیید لغو/تکمیل یکپارچه شدند.
- ثبت‌نام داروخانه به چهار مرحله با حفظ اطلاعات در حافظه هنگام رفت‌وبرگشت تبدیل شد. ایجاد حساب روی سرور در ارسال نهایی انجام می‌شود؛ ذخیره خودکار پیش‌نویس قبل از ایجاد حساب ادعا نشده است.
- پنل‌ها با کارت‌های ساده، داده‌های واقعی، میان‌برهای کاربردی و حالت خالی روشن یکپارچه شدند. پنل مدیریت و داروخانه در موبایل منوی پایین و کشوی ناوبری دارند.
- فهرست نسخه داروخانه جست‌وجو، فیلتر، مرتب‌سازی، صفحه‌بندی واقعی و کارت موبایل دارد. جزئیات، پاسخ موجودی، وضعیت ثبت‌نام، پروفایل، مدارک و بررسی ثبت‌نام توسط مدیر هماهنگ شدند.
- برچسب رد ثبت‌نام و رد مدرک از عدم موجودی نسخه جدا شد. خطای خروج دیگر به‌عنوان خروج موفق پنهان نمی‌شود.

## طراحی، تصاویر و واکنش‌گرایی

- فارسی و RTL، فونت محلی Vazirmatn Variable، تیترهای بولد، ورودی حداقل ۱۶ پیکسل، رنگ سبز درمانی، زمینه روشن و کنتراست اصلاح‌شده حفظ شده‌اند.
- لوگو و تصاویر موجود پروژه بازاستفاده شدند. پنج تصویر WebP بین ۱۹٬۹۵۰ و ۵۵٬۴۷۶ بایت هستند؛ همه کمتر از سقف ۵۰۰٬۰۰۰ بایت‌اند. لوگوی SVG حدود ۱٫۶ کیلوبایت است.
- جدول‌ها در موبایل به کارت تبدیل می‌شوند؛ Dialog، کشوی منو، Focus Trap، Escape، بازگرداندن فوکوس و Safe Area اصلاح شدند.
- علت واقعی Overflow در RTL، Honeypot خارج از صفحه بود؛ به‌جای مخفی‌کردن Overflow کل صفحه، این ورودی به‌صورت امن و کوچک Clip شد.
- صفحات عمومی در عرض‌های ۳۲۰، ۳۶۰، ۳۹۰، ۴۳۰، ۷۶۸، ۱۰۲۴، ۱۲۸۰ و ۱۴۴۰ پیکسل تست شدند. نتایج دارای پاسخ واقعی نیز در همین هشت عرض بررسی شدند.
- هفت مسیر مدیریت در عرض‌های ۳۹۰ و ۱۴۴۰ پیکسل با ورود واقعی، بدون Overflow و بدون خطای JavaScript بررسی شدند.

## اصلاحات اتصال و امنیت مرتبط

- خطای پیشین `Illegal invocation` در مرورگر با اتصال صحیح `fetch` به محیط اجرایی در کلاینت مشترک رفع و تست رگرسیون اضافه شد.
- تست PostgreSQL خطای مقایسه UUID با Text در قفل سطر Prescription را آشکار کرد. پارامتر همچنان Parameterized است و Cast صریح UUID به آن اضافه شد؛ Schema یا داده موجود تغییر نکرد.
- Token بیمار از URL حذف می‌شود، در Query Key قرار نمی‌گیرد و Cache وضعیت خصوصی بعد از قطع Observer نگه داشته نمی‌شود. تعویض دسترسی، Cache مستقل دارد.
- در Login/Logout، Cache حساب قبلی پاک می‌شود. خروج ناموفق سرور پیام قابل مشاهده دارد و موفقیت کاذب نمایش داده نمی‌شود.
- Guard، RBAC، Tenant Isolation و Authorization مدارک دور زده یا ضعیف نشدند. اعتبارسنجی فایل در UI جایگزین کنترل Backend نیست.
- نسخه‌های Android و iOS در Capacitor با Core نصب‌شده در ۷٫۶٫۹ هماهنگ شدند. به‌روزرسانی محدود Platform Express به ۱۱٫۲٫۷، Multer به ۲٫۴٫۰ و proxy-addr به ۲٫۰٫۸، هشدارهای مربوط آن‌ها را در Audit برطرف کرد.
- هیچ Secret یا ENV محلی در تغییرات Source قرار نگرفت. بررسی نهایی مسیرهای تغییرکرده، استفاده‌ای از `any`، `@ts-ignore`، `dangerouslySetInnerHTML` یا LocalStorage برای Token نشان نداد.

| `npm run build`            | PASS                          |

| `npm audit --omit=dev`     | FAIL؛ ۵ هشدار باقی است        |

Integration با ENV محلی بارگذاری‌شده، `NODE_ENV=test` و PostgreSQL/Redis واقعی اجرا شد. تست‌های پاک‌سازی فقط رکوردهای موقت همان اجرا را حذف کردند. تغییر تنظیمات یا حذف داده کاربر انجام نشد.

تست‌های E2E معمول شامل نام نهایی در عنوان و Manifest، ناوبری به فرم، منوی موبایل و فوکوس، لینک بخش‌ها، اعتبارسنجی و برگشت مرحله ثبت‌نام، رد لینک ناقص، Axe و هشت عرض صفحه هستند. این ۱۶ تست به‌تنهایی ادعای پوشش کل امکانات Backend نیستند.

علاوه بر آن، یک Smoke واقعی مرورگر روی برنامه در حال اجرا انجام شد: فرم بیمار درخواست را در PostgreSQL ایجاد کرد؛ دو حساب موقت داروخانه وارد شدند و از رابط، پاسخ FULL و PARTIAL ثبت کردند؛ بیمار نتایج مرتب‌شده را دید و از Dialog یک داروخانه را انتخاب کرد. مقدار `SELECTED_PHARMACY` و بسته‌شدن Assignment دیگر مستقیماً در Database بررسی شدند. این Smoke از داروخانه‌های تأییدشده موقت استفاده کرد و تأیید ثبت‌نام توسط مدیر را از UI پوشش نداد. تمام رکوردهای همان Smoke پاک شدند.

بررسی Axe روی شش مسیر عمومی در تست‌های مرورگر، هفت مسیر مدیریت در دو عرض، جزئیات دو داروخانه و وضعیت منتخب بیمار، نقض خودکار WCAG 2 A/AA و 2.1 AA گزارش نکرد. این نتیجه جایگزین بررسی کامل دستی WCAG یا تست Screen Reader واقعی نیست.

Offline/Online مرورگر نیز واقعی تغییر کرد: اطلاعات فرم در حافظه حفظ شد، هیچ POST در حالت Offline ارسال نشد و بعد از اتصال نیز ارسال مخفی یا Queue خودکار رخ نداد.

## محدودیت‌های باقی‌مانده

- Audit تولید هنوز ۵ هشدار در زنجیره‌های `@nestjs/swagger`/`js-yaml` و `prisma`/`@prisma/config`/`deepmerge-ts` دارد: ۳ High و ۲ Moderate، بدون Critical. Audit کل با ابزارهای توسعه ۲۲ هشدار شامل ۴ Critical، ۱۱ High و ۷ Moderate دارد. بنابراین سلامت کامل وابستگی‌ها یا آمادگی امنیتی Production ادعا نمی‌شود؛ ارتقای عمده ابزارهای موجود خارج از دامنه این بازطراحی بوده است.
- Build درباره Chunk اصلی حدود ۵۰۰٫۳۷ کیلوبایت هشدار می‌دهد؛ Gzip آن حدود ۱۴۷٫۳۸ کیلوبایت است. Code Splitting مسیرها فعال است و Warning پنهان نشده است. Lighthouse یا LCP روی شبکه موبایل واقعی اندازه‌گیری نشد.
- `cap sync` موفق است، ولی پلاگین Secure Storage خارجی همچنان `Package.swift` ندارد و هشدار SPM باقی است. ساخت امضاشده APK/AAB یا iOS Archive، شبیه‌ساز، Secure Storage روی دستگاه و Keyboard/Back Button روی دستگاه در این مرحله تأیید نشده‌اند.
- دامنه HTTPS نهایی، Signing و استقرار Production در این بازطراحی انجام نشده‌اند. URL فعال این محیط، سرور توسعه است.

## اجرای محلی

با سرویس‌های PostgreSQL، Redis و MinIO و فایل ENV محلی مطابق مستندات پروژه:

```bash
npm run dev:api
npm --workspace apps/web run dev -- --port 5174 --strictPort
```

رابط: `http://localhost:5174/`، API Health: `http://localhost:4000/health`.

برای Build و کپی خروجی جدید داخل پروژه‌های Native:

```bash
npm run build
npm run cap:sync
```
